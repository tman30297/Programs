Constraints
Constraints is a crucial and fundamental concept in iOS development. In fact, theskill of a UI developer can be determined by how well he/she can manage andutilize the constraints.
Constraints ensure that UI elements maintain their positions and sizes consistentlyacross different devices. When you apply a constraint to an element, it’s liketelling an element what to do and what not to do.
For example, you can use constraints to ensure that the label maintains a height of30 and a width of 30 on all screen sizes, or to keep the label centered bothvertically and horizontally across all screen sizes. This facility is provided byApple through the concept called Auto Layout. By defining the constraints, AutoLayout automatically adjusts the layout for all the screen sizes according to theconstraints given.
Auto Layout
Auto Layout automatically calculates the position and the size of the views placedin the view hierarchy based on the constraints applied to them. For betterunderstanding, think of Auto layout as the interior decorator of our screen. Just asan interior decorator arranges furniture according to the rules the interior designergave him/her, Auto layout arranges UI elements (like views, buttons, and labels)according to the constraints provided. You specify the elements and constraints,and Auto layout adjusts the screen for you.

The Story Behind the Scales
There is not much story behind the scales, if your device is like an older Appledevice, such as an old iPhone or iPad device which is of low resolution then the1x images are used, if your device is a retina device then 2x images are used andif it is with much higher resolution, then 3x images are used. It’s all about savingthe user’s device space. This concept is called app slicing, where the user’s devicewill only do the things that are required. For example, if the user’s device is anon-retina old iPhone, it will not download retina images at 2x resolution.
In some cases, the designer gives a vector image, one image for all theresolutions.

Show : When you have a show segue, this will push the target viewcontroller to the top, that is the target view controller will present with theback button.
Show Detail : This is used when ViewControllers are in
UISplitViewController . This will update the detail view side of the
UISplitView with the target ViewController .
Present Modally : When you use this segue, the target ViewController
modally, you don’t get a ‘back’ button with this. You can swipe down todismiss this target ViewController . This target ViewController doesn’thave to be a part of the navigation stack.
Present As Popover : When you use this segue for iPhone, you will see thetarget view controller is presented modally, the true effect can be seen in theiPad, where the target ViewController will be presented as the popover atthe center of the screen.
Custom: You can use this custom segue and get the transition to the target
ViewController in your own way.

The famous companies that use S3 for their web content storage are Pinterest,Reddit, Netflix, and Airbnb. Interestingly, Amazon itself uses the S3 service tostore project data.

Time for learning new important and awesome topics. This will allow you to learnhow the authentication of any app works. The Big Why
Auth0 gives us the enterprise–level feature such as SSO (Single Sign-On) superquick. This can help us save money and time; by not needing countless months ofdevelopment, it gives setup of Google-level authentication. Money and time willbe hugely saved using Auth0.
OAuth 2.0
OAuth 2.0 is a framework that that gives end users access and the protocolsnecessary for authorization.
We can create our own protocols for authorization, but the one we create may notbe up to standard; OAuth 2.0 is the best and can be implemented on mobile orweb.
Coming to Auth0, it is a company that provides OAuth 2.0 authorization; it can bethought of as a wrapper around OAuth2.0. Using Auth0, we do not have to writethe code for user management; everything is done via auth0.
Working of Auth0
From the following diagram, you will be able to understand how Auth0 works:

--- Page 448 ---
Figure 9.8: Workings of Auth0
Working Flow of Auth0
1. User clicks Login button in our app.
2. Auth0’s SDK redirects our user to Auth0 Authorization Server using(/authorize).
3. Auth0 Authorization Server prompts the user to login with an authorizationprompt.
4. User authenticates with one of the Auth0 configured login options and willsee a consent prompt listing the permissions Auth0 will give to theapplication.
5. Auth0 Authorization Server sends user back to our App with single-useauthorization code.
6. Auth0’s SDK sends authorization code, application’s client ID, andapplication’s credentials, such as client secret and Private Key JWT, toAuth0 Authorization Server ( /oauth/token ).
7. Auth0 Authorization Server verifies authorization code, application’s clientID, and our app’s credentials.
8. Auth0 Authorization Server sends back ID token and access token.

--- Page 449 ---
9. Our app can use the access token to call the Auth0 API to get informationabout the user.
10. API responds with requested data, such as user information.
