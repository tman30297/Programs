## 1. Prompt Engineering Best Practices

### Overview
Prompt engineering is the discipline of developing and optimizing prompts to effectively use language models for various applications. It encompasses skills for interfacing, building with, and understanding LLM capabilities.

### Key Techniques

#### Zero-Shot Prompting
- Direct prompting without examples
- Works well for simple tasks
- Models like GPT-4 show strong zero-shot capabilities

#### Few-Shot Prompting
- Provides demonstrations in the prompt to enable in-context learning
- Label space and input text distribution matter (Min et al., 2022)
- Random labels still outperform no labels
- Format consistency helps performance

#### Chain-of-Thought (CoT) Prompting
- Encourages models to show reasoning steps
- Particularly effective for complex arithmetic, commonsense, and symbolic reasoning
- Can be combined with few-shot (include reasoning examples)

#### System Prompts
- Define model behavior and personality
- Set boundaries and constraints
- Critical for production applications

### Best Practices
1. **Be specific and clear** - Ambiguous prompts produce ambiguous results
2. **Use examples wisely** - Few-shot works for pattern learning
3. **Structure your prompts** - Clear sections for context, instructions, and output format
4. **Iterate and test** - Prompt optimization is empirical
5. **Consider model differences** - Techniques that work for one model may not transfer

### Tools & Frameworks
- **LangChain** - Offers prompt templates and optimization
- **LangSmith** - For tracing and evaluating prompt performance
- **Prompt Playground** - OpenAI's interface for testing

## 2. Vector Databases

### Overview
Vector databases store data alongside vector embeddings and provide fast similarity search at scale. They are essential for AI applications requiring semantic search, RAG pipelines, and agent memory.

### Core Concepts

#### Vector Embeddings
- Numerical representations of unstructured data (text, images, etc.)
- Generated by embedding models (e.g., OpenAI ada-002, sentence-transformers)
- Similar items cluster together in vector space

#### Similarity Search
- Find objects close to each other in vector space
- Common metrics:
  - **Cosine similarity** - Most common for NLP
  - **Euclidean (L2) distance** - Straight-line distance
  - **Dot product** - For normalized vectors

#### Vector Indexing (ANN)
- Approximate Nearest Neighbor algorithms enable fast retrieval at scale
- **HNSW** (Hierarchical Navigable Small World) - Default in Weaviate, good balance of speed/accuracy
- **FAISS** - Facebook's clustering-based approach
- **ANNOY** - Tree-based indexing
- **LSH** - Hash-based indexing

### Architecture
- Multiple indices (object, inverted, vector storage)
- Sharding and replication for scale
- Support for metadata filtering

### Use Cases
- **LLM RAG pipelines** - Retrieve relevant context
- **Agent memory** - Store past interactions
- **Semantic search** - Meaning-based retrieval
- **Recommendation systems** - Find similar products/content

### Popular Tools
- **Weaviate** - Open source, cloud-native
- **Pinecone** - Managed vector database
- **Chroma** - Open source, lightweight
- **Milvus** - Open source, scalable
- **Qdrant** - Rust-based, high performance
- **FAISS** - Library (not full database)
- **PostgreSQL + PGVector** - For existing PG deployments

## 3. RAG Architectures

### Overview
Retrieval Augmented Generation (RAG) combines retrieval systems with LLMs to produce grounded, accurate responses. It addresses LLM limitations like hallucinations and knowledge cutoff.

### Core Components

#### 1. Indexing Pipeline (Offline)
- **Document Loaders** - Load data from various sources
- **Text Splitters** - Chunk documents into manageable pieces
- **Embeddings Model** - Convert chunks to vectors
- **Vector Store** - Index and store embeddings

#### 2. Retrieval & Generation (Runtime)
- **User Query** → Embed → Similarity Search → Top-K chunks
- **Context** + **Query** → LLM → **Response**

### Architecture Patterns

#### Basic RAG
- Simple retrieval → pass to LLM
- Fast, effective for straightforward queries
- LangChain example: ~40 lines of code

#### Agentic RAG
- LLM decides when to retrieve
- Can use multiple tools
- More flexible, handles complex queries
- Uses LangChain agents with tool definitions

#### Multi-hop RAG
- Iterative retrieval
- Each step builds on previous context
- For complex reasoning tasks

#### Hybrid Search
- Combine vector search with keyword search
- BM25 + semantic search
- Better for exact matches + semantic understanding

### Best Practices

#### Chunking
- **Size matters** - Too small loses context, too big noisy
- **Overlap** - 10-20% overlap preserves context
- **Recursive splitting** - Better than fixed-size

#### Retrieval Optimization
- **Top-K tuning** - Balance relevance vs. noise
- **Reranking** - Add a reranker model for better results
- **Metadata filtering** - Filter before vector search

#### Context Handling
- **Prompt engineering** - How to format retrieved context
- **Citation** - Include sources in response
- **Window management** - Handle context length limits

### Implementation Frameworks
- **LangChain** - Most popular, extensive integrations
- **LangGraph** - For complex orchestration
- **LlamaIndex** - Specialized for RAG
- **Deep Agents** - LangChain's batteries-included approach

### Evaluation
- **LangSmith** - Trace and evaluate RAG pipelines
- **RAGAs** - Specific metrics for RAG
- **Human evaluation** - Still important for quality

## Key Takeaways

1. **Prompt Engineering** is essential for getting the best from LLMs. Start with clear instructions, use examples for complex tasks, and iterate.

2. **Vector Databases** are the backbone of AI applications requiring memory and retrieval. Choose based on scale needs, deployment preferences, and performance requirements.

3. **RAG** is the dominant pattern for building accurate AI systems with domain knowledge. Start simple, then add complexity (agentic, multi-hop) as needed.

4. **The Ecosystem** is rapidly evolving. LangChain/LangGraph dominate the framework space, with Weaviate and Pinecone leading vector DBs.
