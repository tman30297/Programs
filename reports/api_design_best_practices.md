# API Design Best Practices - Quick Reference

## RESTful API Design

### URL Structure
```
GET    /api/v1/users          # List users
GET    /api/v1/users/123      # Get single user
POST   /api/v1/users          # Create user
PUT    /api/v1/users/123      # Full update
PATCH  /api/v1/users/123      # Partial update
DELETE /api/v1/users/123      # Delete user
```

### HTTP Status Codes
- **2xx Success**: 200 OK, 201 Created, 204 No Content
- **4xx Client Error**: 400 Bad Request, 401 Unauthorized, 403 Forbidden, 404 Not Found, 422 Unprocessable
- **5xx Server Error**: 500 Internal Server Error, 503 Unavailable

### Query Parameters
- Pagination: `?page=2&limit=20`
- Sorting: `?sort=-created_at,name`
- Filtering: `?status=active&role=admin`
- Fields: `?fields=id,name,email`

### Request/Response Format
```json
// Request
{
  "name": "John Doe",
  "email": "john@example.com"
}

// Response (single)
{
  "data": {
    "id": "123",
    "name": "John Doe",
    "email": "john@example.com",
    "created_at": "2026-03-14T10:00:00Z"
  }
}

// Response (collection)
{
  "data": [...],
  "meta": {
    "total": 100,
    "page": 1,
    "limit": 20
  }
}
```

## Error Handling
```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Invalid input",
    "details": [
      {"field": "email", "message": "Invalid email format"}
    ]
  }
}
```

## Versioning
- URL path: `/api/v1/...`
- Header: `Accept: application/vnd.myapp.v1+json`
- Recommended: URL path (most explicit)

## Authentication
- **JWT**: Stateless, good for APIs
- **API Keys**: Simple, good for server-to-server
- **OAuth 2.0**: When third-party access needed
- **Bearer token**: `Authorization: Bearer <token>`

## Rate Limiting
- Header: `X-RateLimit-Limit`, `X-RateLimit-Remaining`, `Retry-After`
- Common: 100-1000 requests/minute

## Best Practices Summary
1. Use HTTPS always
2. Version your APIs from day one
3. Use proper HTTP methods
4. Return appropriate status codes
5. Paginate collections
6. Support filtering and sorting
7. Use consistent naming (snake_case or camelCase)
8. Document with OpenAPI/Swagger
9. Implement rate limiting
10. Version your APIs
